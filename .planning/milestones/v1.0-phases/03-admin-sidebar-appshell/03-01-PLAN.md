**1. Create `app/src/components/AdminSidebar.tsx`:**

This component is the single source of truth for admin navigation links. It will be rendered in both the desktop fixed sidebar and the mobile Sheet drawer by AppShell (Plan 02).

```tsx
import { NavLink } from 'react-router-dom';
import { cn } from '@/lib/utils';
import { useAuthStore } from '@/lib/auth';
import ThemeToggle from '@/components/ThemeToggle';
```

**Props interface:**

```tsx
interface AdminSidebarProps {
  onNavigate?: () => void;
}
```

The `onNavigate` callback is called when a nav link is clicked. The mobile Sheet passes `() => setMobileOpen(false)` to close the drawer on navigation. Desktop passes nothing.

**Nav items array** (defined outside the component for stability):

```tsx
const navItems = [
  { to: '/', label: 'Dashboard', end: true },
  { to: '/assessments', label: 'Assessments' },
  { to: '/question-banks', label: 'Question Banks' },
  { to: '/sessions', label: 'Attendance' },
  { to: '/students', label: 'Students' },
  { to: '/bug-reports', label: 'Bug Reports' },
] as const;
```

NOTE: The `end: true` on Dashboard is CRITICAL — without it, `<NavLink to="/">` matches every URL. Only Dashboard needs `end`.

**Component structure:**

- Outer `<div className="flex h-full flex-col">` — fills sidebar height
- **Sidebar header:** `<div className="flex items-center justify-between border-b border-border/50 px-4 py-4">` containing:
  - `<span className="text-lg font-semibold text-foreground">MedEdPrep</span>`
  - `<ThemeToggle />` — moved from AdminLayout header per THM-06 / research Open Question 3 recommendation
- **Nav section:** `<nav className="flex-1 space-y-1 overflow-y-auto px-3 py-4">` containing:
  - Map over `navItems`, rendering each as a `<NavLink>`:
    ```tsx
    <NavLink
      key={to}
      to={to}
      end={end}
      onClick={() => onNavigate?.()}
      className={({ isActive }) =>
        cn(
          'flex items-center rounded-md px-3 py-2 text-sm font-medium transition-colors',
          isActive
            ? 'nav-active bg-primary/10 text-primary'
            : 'text-muted-foreground hover:bg-accent hover:text-accent-foreground',
        )
      }
    >
      {label}
    </NavLink>
    ```
  - After the map, conditionally render the Instructors link when `user?.role === 'owner'`:
    ```tsx
    {
      user?.role === 'owner' && (
        <NavLink
          to="/instructors"
          onClick={() => onNavigate?.()}
          className={({ isActive }) =>
            cn(
              'flex items-center rounded-md px-3 py-2 text-sm font-medium transition-colors',
              isActive
                ? 'nav-active bg-primary/10 text-primary'
                : 'text-muted-foreground hover:bg-accent hover:text-accent-foreground',
            )
          }
        >
          Instructors
        </NavLink>
      );
    }
    ```
  - Use `onClick={() => onNavigate?.()}` (optional chaining) on EVERY NavLink. This satisfies TypeScript `noUnusedParameters` and handles the undefined case when desktop doesn't pass the callback.
- **Footer section:** `<div className="border-t border-border/50 px-4 py-3">` containing:
  - `<p className="truncate text-xs text-muted-foreground">{user?.email}</p>`
  - `<button onClick={logout} className="mt-1 text-xs text-muted-foreground hover:text-foreground transition-colors">Sign out</button>`

Use `useAuthStore` to get both `user` and `logout`:

```tsx
const user = useAuthStore((s) => s.user);
const logout = useAuthStore((s) => s.logout);
```

Export as default: `export default function AdminSidebar({ onNavigate }: AdminSidebarProps)`.

**2. Add Glass Purple CSS rules to `app/src/index.css`:**

Add the following rules AFTER the existing `.sd-root-modern` block at the end of the file. These use `[data-theme]` CSS selectors following Phase 2's established pattern — NO inline React style logic. The `data-theme` attribute is set by the ThemeProvider from Phase 2.

```css
/* === Phase 3: Admin Sidebar Glass Effects === */

/* LAY-06: Body gradient in Glass Purple */
[data-theme='glass-purple'] body {
  background: radial-gradient(ellipse at top, #2d1b69 0%, #0f0a1e 100%);
  min-height: 100vh;
}

/* LAY-07: Glass sidebar blur */
[data-theme='glass-purple'] .sidebar-glass {
  background: rgba(255, 255, 255, 0.05);
  backdrop-filter: blur(16px);
  -webkit-backdrop-filter: blur(16px);
  border-right: 1px solid rgba(255, 255, 255, 0.1);
}

/* LAY-08: Active nav item — glass glow in Glass Purple */
[data-theme='glass-purple'] .nav-active {
  background: rgba(139, 92, 246, 0.2) !important;
  box-shadow: 0 0 12px rgba(139, 92, 246, 0.3);
  color: #c4b5fd !important;
}

/* LAY-08: Active nav item — primary highlight in Daylight */
:root .nav-active,
[data-theme='daylight'] .nav-active {
  background: var(--primary-alpha, rgba(27, 95, 208, 0.1));
  color: var(--primary, #1b5fd0);
}
```

NOTES on the CSS:

- The `!important` on glass-purple `.nav-active` overrides the inline Tailwind `bg-primary/10` and `text-primary` classes applied by NavLink. This ensures the glass glow visually takes priority without requiring theme-conditional JSX.
- The `:root .nav-active` rule uses `var(--primary)` which resolves correctly after Phase 1 CSS migration. The `var(--primary-alpha, rgba(...))` provides a fallback for the semi-transparent background.
- The `-webkit-backdrop-filter` prefix is needed for Safari support.
- The `min-height: 100vh` on body ensures the gradient covers full viewport even on short pages.
- The `sidebar-glass` class will be applied by AppShell (Plan 02) to the sidebar container elements.
