**Block 1: Smooth theme transition (CMP-06)**

Add this inside the existing `@layer base` block (or as a new `@layer base` block):

```css
@layer base {
  *,
  *::before,
  *::after {
    transition:
      background-color 0.25s ease,
      color 0.15s ease,
      border-color 0.25s ease,
      box-shadow 0.25s ease;
  }
}
```

This applies transitions to all elements so that when `data-theme` toggles, colors animate smoothly. The FOUC prevention script from Phase 2 ensures no visible transition on initial page load.

**CRITICAL:** Do NOT include `backdrop-filter` in the transition properties. The REQUIREMENTS.md explicitly marks animating backdrop-filter as out of scope (performance trap per NN/G research). Only animate background-color, color, border-color, and box-shadow.

**CRITICAL:** The existing `.sd-root-modern *` border-color revert block MUST be preserved exactly as-is. Do NOT modify it. The new transition rule on `*` should NOT conflict because transitions and border-color-revert operate on different CSS properties.

**Block 2: Glass card effect (CMP-04)**

Add a utility rule that applies glass morphism to cards when Glass Purple theme is active:

```css
/* Glass card effect — activated via .glass-card className on Card component */
[data-theme='glass'] .glass-card {
  background: rgba(255, 255, 255, 0.06);
  backdrop-filter: blur(12px);
  -webkit-backdrop-filter: blur(12px);
  border-color: rgba(255, 255, 255, 0.12);
}
```

This uses a `.glass-card` class approach (cleaner and more explicit than targeting `.bg-card` directly). The rule only fires when `data-theme="glass"` is set AND the element has the `glass-card` class. In Daylight (no `data-theme` attribute or `data-theme="daylight"`), the rule does not apply and the Card renders with its default solid `bg-card` background.

Do NOT use `!important`. The specificity of `[data-theme='glass'] .glass-card` should be sufficient. If it isn't (because Tailwind `bg-card` has higher specificity), add `!important` ONLY to the `background` property as a last resort.

Do NOT use Tailwind opacity modifiers like `bg-card/50` — they do not work with raw hex CSS variables post-Phase-1 migration.

**Block 3: Primary button glow on hover (CMP-05)**

Add a rule for the purple glow effect on primary buttons during Glass Purple:

```css
/* Primary button glow — Glass Purple hover effect */
[data-theme='glass'] button.bg-primary:hover,
[data-theme='glass'] a.bg-primary:hover,
[data-theme='glass'] [role='button'].bg-primary:hover {
  box-shadow:
    0 0 0 1px rgba(139, 92, 246, 0.3),
    0 0 20px 4px rgba(139, 92, 246, 0.4);
}
```

The glow color `rgba(139, 92, 246, ...)` maps to purple-500 at variable opacity. This should visually match the Glass Purple `--primary` value. If Phase 1 set `--primary` to a different purple hex under `[data-theme="glass"]`, adjust the rgba values to match. Check the `[data-theme="glass"]` `--primary` value in `index.css` and derive the glow color from it.

The `box-shadow` transition is already covered by Block 1's universal transition rule, so the glow will animate in/out smoothly on hover.
