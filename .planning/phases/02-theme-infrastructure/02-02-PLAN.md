Create `app/src/components/ThemeToggle.tsx` as a default-exported React component following the project's component conventions (PascalCase file, default export).

Implementation following research Pattern 3 exactly:

```tsx
import { Sun, Moon } from 'lucide-react';
import { Button } from '@/components/ui/button';
import { useTheme } from '@/contexts/ThemeContext';

export default function ThemeToggle() {
  const { theme, toggleTheme } = useTheme();

  return (
    <Button
      variant="ghost"
      size="icon"
      onClick={toggleTheme}
      aria-label={
        theme === 'daylight' ? 'Switch to Glass Purple theme' : 'Switch to Daylight theme'
      }
    >
      {theme === 'daylight' ? (
        <Moon className="h-4 w-4" aria-hidden="true" />
      ) : (
        <Sun className="h-4 w-4" aria-hidden="true" />
      )}
    </Button>
  );
}
```

Key details:

- Uses `lucide-react` Sun and Moon icons (already installed in project)
- Uses shadcn `Button` with `variant="ghost"` and `size="icon"` (both variants confirmed available in project's button.tsx)
- `aria-label` describes the ACTION (what clicking will do), not the current state — this is the correct accessibility pattern
- Moon icon shown in Daylight (clicking will switch to dark), Sun icon shown in Glass Purple (clicking will switch to light) — this is standard sun/moon UX
- Does NOT use `useEffect`, does NOT subscribe to system preference changes — the toggle is purely manual user action
- `aria-hidden="true"` on icons since the Button has an `aria-label`
